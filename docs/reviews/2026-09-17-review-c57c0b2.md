## BLOCKING

### B1. `SKIPPED` is folded into `Overall: PASS`, exit 0 and JSON `status: "PASS"` — and the shipped CI will actually hit this
- `tools/repo-check.py:141` (yaml), `:184`, `:201` (JS) return `SKIPPED` with the text "*this is not a pass*".
- `tools/repo-check.py:288,293` only clear `worst_ok` on `FAIL`; `:305` emits `'status': 'PASS'`, `:322` prints `Overall: PASS`, `:325` returns exit 0.

Reproduced: running with `node` off `PATH` gives `[SKIPPED] javascript-syntax-authored`, `[SKIPPED] javascript-parse-evidence`, **`Overall: PASS`, exit 0**, and `--json` reports top-level `"status": "PASS"`. A downstream consumer reading `report["status"]` sees a green result for a run in which two checks never executed.

Why it matters here specifically: `.github/workflows/source-checks.yml:36-38` uses `actions/setup-python@v5` with no `pip install pyyaml` step. `actions/setup-python` ships a vanilla CPython (pip/setuptools/wheel only) and shadows the runner's system Python, so `yaml-parse` will report `SKIPPED` on **every** CI run while the job goes green. That is precisely the pattern `AGENTS.md:46` forbids ("never relabel a blocked check as passed") and that `docs/BUILD-AND-TEST.md:23,30` promises against ("Reports `SKIPPED` — not a pass"). It also makes `.github/workflows/source-checks.yml` unable to detect a malformed workflow file, which is the stated reason the yaml check exists (`tools/repo-check.py:131`).

Two-line fix: add `pip install pyyaml` to the workflow, and make the aggregate non-green (or a distinct `INCOMPLETE`) when any check is `SKIPPED`. I could not execute GitHub Actions to confirm the PyYAML absence empirically; the local-PATH reproduction of the SKIPPED→PASS roll-up is confirmed.
