### NBR-3 — the prototype-`user` control cannot fail
`candidate/tests/host-envelope.test.mjs:117-120` vs `candidate/a605/host-envelope.mjs:99`.

Replacing `Object.prototype.hasOwnProperty.call(envelope, 'user') ? envelope.user : undefined` with a plain `envelope.user` leaves the suite at **484 passed, 0 failed**.

Cause: `JSON.parse('{"facts":[],"__proto__":{"user":"hello"}}')` creates `__proto__` as an **own data property**; the object's actual prototype stays `Object.prototype`. Verified: own keys `['facts','__proto__']`, `hasOwnProperty('user') === false`, `env.user === undefined`. Guarded and unguarded reads agree, so the assertion passes for the wrong reason.

The guard is genuinely useful — under `Object.prototype.user = 'pwned'` the unguarded read returns `'pwned'` while `parseHostPrompt` correctly returns `envelope-user-is-not-a-string`. It is simply **untested**. A discriminating control must pollute `Object.prototype` (and restore it), not use a `__proto__` JSON key.

### NBR-5 — NB8 is partially applied; `selection.find()` still trusts object semantics
`candidate/a605/answer-boundary.mjs:50`, comment at `:55-59`.

NB8's claimed fixes **do work** (forged `includes()` → `CANDIDATE_FIELD_NOT_APPROVED`; forged `some()` → same; prototype-only `fields` value → `CANDIDATE_MISSING_VALUE`), and there are **no false rejections** — plain objects, `Object.create(null)` records, `Object.create(null)` fields and frozen arrays all still bind correctly.

But the record *lookup itself* is unhardened:
```js
const source = selection.find((s) => s.id === ref.sourceId);   // :50 — selection never checked to be an Array
```
Reproduction — a non-array selection with a forged `find()` admits an arbitrary record:
```js
buildTypedFact({ find: () => ({id:'s1',revision:1,approvedFields:['vitality'],
                               fields:{vitality:5},authorityEpoch:0,permissionRevision:1}) },
               {epoch:0,permissionRevision:1}, {sourceId:'s1',revision:1,field:'vitality'})
// => ADMITTED, value 5
```
Also `const approved = source.approvedFields` (`:60`) is a prototype-traversing read: a record with `approvedFields` on its prototype is admitted and renders values with a citation. Same for `revision` / `authorityEpoch` / `permissionRevision`.

`selection` is caller-supplied by the integration, not by an attacker-controlled envelope, so this is not a demonstrated exploit path — but it is the *same class* as the `includes()` bypass NB8 fixed, and the comment's *"Both are now read structurally"* overstates completeness. Suggest `Array.isArray(selection)` + a `for…of` identity scan.
