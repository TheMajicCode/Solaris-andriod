# Artifacts

This repository tracks **source and documentation**. It does not track binaries,
model weights, build inputs or private evidence — and no artifact release has
been created by this import.

## Where each kind of material belongs

| Material | Destination |
| --- | --- |
| Reviewed application/reconstruction source, tests, scripts, contracts, docs | Normal Git history, by explicit allowlist |
| Useful recovery evidence and decompiled references | Tracked as text where size, licensing and privacy permit, with clear evidence labels and source hashes |
| Toolchains, model weights, reference APKs, large generated bytecode | A curated **private** release asset or private artifact store, referenced by immutable hash and size |
| Full original 1.52 GB handoff | Preserved privately outside ordinary Git. **Do not upload it unchanged** — it contains private phone evidence. |
| Phone screenshots/recordings, patient records, raw vaults, recovery secrets, wallet seeds, signing credentials | Excluded from Git, Actions artifacts, release assets and issue/PR bodies |
| Synthetic test data, redacted/synthetic showcase assets | Git, or a documented private bundle, after provenance and privacy review |

## Rules for any future artifact work

- **SHA-256 is content identity.** A tag or asset URL is not immutable; a hash is.
- Never commit an expiring signed URL, token or credential.
- Review each archive's complete entry list for privacy, secrets, license and
  restoration safety **before** upload, and verify hashes again after upload.
- Separate the model experiment input from the minimum test/tool input, so no one
  is forced into a large download they do not need.
- Check licenses before redistributing third-party tools or weights. If
  redistribution rights are not established, retain hashes and authorized
  acquisition instructions and **report the restore path blocked**.
- Restoration is manual and checksum-checked: reject unsafe paths and unexpected
  files, and never overwrite newer working source while restoring inputs.
- Mark any archived-input release as historical reference input, not a new
  production app release.
- Keep artifact-upload jobs separate from untrusted PR execution. No signing keys
  in ordinary PR CI.

## Size limits to design around

| Limit | Value |
| --- | --- |
| GitHub browser upload | 25 MiB per file |
| Ordinary Git warning | over 50 MiB |
| Ordinary Git rejection | over 100 MiB |
| Release asset | under 2 GiB each; access follows repository read permissions |

The full handoff fits the release-size limit, but its private evidence makes an
unchanged upload inappropriate regardless.
