## BLOCKING (fix before push)

### B1. `frozen_external_records` can launder arbitrary drift in an imported file into a PASS
`tools/solaris_checks/checks.py:105-109` (in `check_frozen_integrity`)
```python
expected = {e['tracked_path']: e for e in ctx.import_manifest['files']}
for record in ctx.candidate.get('frozen_external_records', []):
    expected[record['path']] = {'sha256': record['sha256'], 'bytes': record['bytes']}
```
The loop **overwrites** import-manifest entries. Any imported file can be edited and made green by appending a `frozen_external_records` entry with the new hash — and unlike `candidate_overrides`, that entry requires **no** `original_sha256`, no `rationale`, no `integration_target`, and is validated by nothing (`check_candidate_changes` only validates `candidate_overrides`, `inherited_defects` and `maintained_candidate_paths`).

This directly defeats `CANDIDATE-CHANGES.json` rule 2 ("Refreshing a baseline hash to absorb a modification is prohibited. Record an override instead.") and AGENTS.md's "the frozen reference never changes to accommodate a repair".

Verified (scratchpad copy):
```
appended "LAUNDERED CONTENT INJECTED BY REVIEWER" to Solaris-Android-R2/BUILD-REPORT.md
added {"path": <that file>, "sha256": <new>, "bytes": <new>}  to frozen_external_records
python3 tools/repo-check.py  -> EXIT=0
[PASS] frozen-integrity  (1881/1881 files)
Overall: PASS
git diff --stat -- Solaris-Android-R2/BUILD-REPORT.md -> 1 file changed, 2 insertions(+)
```
Fix: only accept a `frozen_external_records` entry for a path **absent** from the import manifest (rule 5 already says this in prose), and give the record the same required-field validation as an override.
