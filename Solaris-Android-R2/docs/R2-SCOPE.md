# R2: executable host reconstruction and candidate feasibility

This cycle continues the authorized controlled reconstruction. Code 601 remains
the baseline. No original input or completed R0/R1 checkpoint is changed.

The immediate scope is the compiled QvacService lifecycle owner (Metro module
591, Hermes factory 7139). Recover readable behavior for its constructor,
operation guard, cancellation/settlement, operation dispatch, worker startup and
lifecycle queue. Compare that source with the original bytecode running on the
matching Hermes VM under explicit synthetic dependencies. Then assess a repair
and integration route. Passing isolated helper tests is insufficient.

Independent review must identify the exact source it reviewed. Every build
cycle needs targeted tests. A signed candidate remains conditional on verified
compatibility, including the actual application integration. Original DEX,
native libraries, vault formats, identities, model definitions and retained
records are outside this repair scope. No installation, data reset, key change,
push or deployment is authorized.

The compiler, runtime and editable harness/build inputs are deliverables. The
test oracle runs synthetic data on a desktop VM. It cannot establish Android
app-state delivery, BareKit transport ordering, vault authorization, persistence
or real model behavior. Those limits remain explicit even if comparisons pass.
