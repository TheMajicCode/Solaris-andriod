## Newer observations

### AND-CI-01 — `node --check` has an ESM blind spot

`node --check file.js` exits 0 for a `.js` file containing ESM syntax **even when
that file has a real syntax error**, because Node's module-syntax detection stops
short of a full module parse. Verified on Node v22.22.2:

```text
export function r(){        .js → exit 0   .mjs → exit 1
function r(){               .js → exit 1   .mjs → exit 1
```

Consequence: the first version of `tools/repo-check.py` — and therefore the
`source-checks` run that passed on `edd43bd` — could have passed a broken
ESM-flavoured `.js` file. No such file exists in the tree today, so no result is
retroactively invalidated, but the green run was weaker evidence than it looked.

Fixed by parsing each file under an explicit `.cjs`/`.mjs` extension and failing
only when both modes fail.

### AND-CI-02 — the skipped-check hole was wider than PyYAML

The foundation plan correctly identified `yaml-parse SKIPPED … Overall: PASS`.
The underlying defect was structural: **any** check could report a non-failing
status without inspecting anything. Checks now fail closed on a missing
dependency, an empty-but-expected scope, or an unexpected exception.

The plan is also right that the second reporting command's `|| true` did not
prove ordinary failures were hidden — the first invocation still failed normally
on a non-zero exit. That construct is nonetheless gone: the checks now run once,
write the report as a side effect, and preserve the real exit status.

### The five file counts are five different sets

`5,234` / `1,879` / `1,878` / `1,867` / `1,917` were being used interchangeably.
They are reconciled, with the identities that must hold, in
[`provenance/SOURCE-LINEAGE.md`](provenance/SOURCE-LINEAGE.md). The tracked-file
total grows as this repository adds its own work and must never be quoted as an
import count.

### Two frozen files sat outside both manifests

The transport authorization prompt and its checksum file arrived on the input
branch rather than inside the pack, so neither the pack inventory nor the repo
import manifest listed them. The new `frozen-integrity` check surfaced this
immediately. They are now hash-pinned under `frozen_external_records`.

## Implementation decisions

| Decision | Rationale |
| --- | --- |
| Two separate integrity models rather than one manifest | The frozen reference must never absorb a repair. Authorized change is recorded in `CANDIDATE-CHANGES.json` with original hash, resulting hash, rationale and integration target. |
| Classification is mandatory and exhaustive | An unclassified path fails. This closes the hole where new source outside `R2/R3/R4` would inherit informational retained-evidence treatment. |
| `AND-IMP-01` registered by exact path **and** hash | A whole-directory downgrade would hide the next real defect. The registration fails if the file changes, disappears, starts parsing, or if any second evidence file breaks. |
| The reference-validation workflow was deleted, not kept as a placeholder | An always-failing job that can never succeed is noise that invites being "fixed" into something dishonest. The gate is reported as BLOCKED by the checker. |
| No linter configured yet | Syntax checks are not lint, and saying so is more useful than a linter mass-applied to decompiled Java and generated `.hasm`. `maintained-source-lint` is listed as a BLOCKED gate. |

## Status of the audit's own limits

These limits from the original audit still stand and are **not** closed by
anything in this repository: no Android lint or Gradle assemble, no whole-app
type checking, no dependency/CVE or complete license audit, no
emulator/device/instrumentation tests, no native crash or disk-full recovery
testing, no real AI benchmarks, no TalkBack or large-text acceptance.

The 287 case executions in the audit remain **287 case executions**, including
the same 63 UI scenarios run against two source forms. They are not 287 unique
end-to-end Android tests, and the 1,675 packaging assertions are not functional
app tests.
